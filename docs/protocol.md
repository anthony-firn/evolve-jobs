# Public listing protocol, version 1

Experimental Nostr kind `30382` (addressable). Tags: `d` = `lever:<board>:<postingId>`, `t` = `evolve-jobs-v1`. `content` is JSON containing the allowlisted fields from `src/core.js:publicJob`. This kind is application-specific and not a registered standard. Event keys identify the publishing node; they do not represent an employer endorsement. Multiple publishers can announce the same source job; clients deduplicate by provider/board/posting ID.

Read verifies event signature, kind, topic, identity, one-day event freshness, future timestamp bounds and payload size. Listing text is rendered as text, never HTML. Apply links are reconstructed from validated provider IDs. Search matching refuses listings fetched more than one day ago. A malicious publisher can still invent text, timestamps or salary. Never submit private data based on peer content: each application client refetches the original employer board and reapplies the local policy. Closed or no-longer-qualifying roles are refused. No public tombstone or exhaustive spam/availability controls exist yet. Relay search is bounded; it is discovery, not a complete job index.

The publication allowlist excludes private profiles, resumes, answers and application history, even if an input object contains them. The publisher refreshes data directly from the provider before signing. Signing keys live in the ignored `private/` directory; do not upload this directory or include it in unencrypted backups. Run under your own operating-system account. Disk encryption and account access controls protect your local data; application-level encrypted storage is not implemented.

Relays observe your IP, public keys, subscriptions and listing content. Employers receive direct API requests and submitted application information. Browser search rules remain in the browser. Employers may run scripts/analytics on their application pages. This repository contains no telemetry, hosted profile service or third-party résumé processor. No resume or application state is sent to Nostr. The donation link opens Fairground's separate support flow.

The extension uses chrome.storage.local for profile, PDF resume, plan and application history; storage sync is never used. It has no externally_connectable entry or web-page message listener. Only its own panel can configure/start a queue; only the tab reserved for the canonical employer URL can receive a profile or report a result. WASM performs text and salary comparisons in the browser and extension. The optional Node worker uses equivalent JavaScript comparisons and a separate SQLite ledger. Do not use both application clients for the same job set. The offline cache contains public app assets only; live employer data is not cached by the service worker.
